# リカパチ（理科の計算 × パチンコ）

理科の計算問題に正解すると、パチンコの抽選権（**保留**）がたまります。保留は自動で抽選され、3つそろえば大当たり。
問題はプログラムで毎回新しく作るので、何度でも遊べます。

- 対象：中学〜高校基礎の理科
- ジャンル：**オームの法則** / **合成抵抗** / **モル計算**
- スマホの縦画面向け。ホーム画面に追加すると、オフラインでも遊べます

> 当たりの抽選は「正解したあと」にだけ行われます。正解しないと当たりは出ません。

---

## 遊び方

1. タイトル画面で **ジャンル** と **難度（★1〜★3）** を選んで「スタート」。
2. 問題に正解すると **保留** が1つたまります（最大4つ）。保留は自動で順番に抽選されます。
3. **速く解くほど・難しい難度ほど**、保留の色が上がって当たりやすくなります。
   問題の上の「いま正解すると ○保留」のメーターで、今の色が分かります（時間がたつと下がります）。
4. 図柄が3つそろえば **大当たり**。玉（スコア）がもらえます。
5. 大当たりの半分は **確変** に入ります。確変中の8問は当たりやすくなるかわりに、難度が1つ上がり、答えは **テンキーで数値入力** になります。
6. まちがえると保留はたまりません。そのかわり、**どんなミスをしたか（ミスの型）** と正しい解き方が表示されます。
7. 「記録」画面で、ジャンル別の正答率とミスの型ごとの回数を見られます。よくするミスに関係する問題は、少し多めに出題されます。

### 保留の色の決まり方

保留の色 ＝ **難度点** ＋ **速さ点**（合計0〜4点）

| | 0点 | 1点 | 2点 |
|---|---|---|---|
| 難度点 | ★1 | ★2 | ★3 |
| 速さ点 | 基準時間より遅い | 基準時間以内 | 基準時間の半分以内 |

基準時間：★1＝20秒、★2＝30秒、★3＝45秒（数値入力のときは1.5倍）

### 当たりやすさ（初期値）

| 合計点 | 保留の色 | 通常時 | 確変中 |
|---|---|---|---|
| 0 | 白 | 15% | 30% |
| 1 | 青 | 22% | 40% |
| 2 | 緑 | 30% | 50% |
| 3 | 赤 | 45% | 65% |
| 4 | 金 | 65% | 85% |

| 項目 | 初期値 |
|---|---|
| 大当たりの出玉 | 通常時 1000玉 / 確変中 1500玉 |
| 確変に入る確率 | 大当たりの50%（確変中の当たりでも同じ） |
| 確変の長さ | 8問（正解も不正解も1問と数える） |
| 確変中の問題 | 難度+1（上限★3）・数値入力 |
| リーチ（見た目だけ） | 当たりは必ずリーチ（うち70%がスーパー）／ハズレは15%でリーチ（うち20%がスーパー） |
| 苦手の出し分け | 直近30問のミスの回数に応じて、関係する問題を「1＋0.25×回数」倍（最大2倍） |

- 保留には、とったときの状態（通常／確変）が記録されます。確変の最後にとった保留は、確変が終わった後で抽選されても確変の確率です。
- 保留が4つたまっているときに正解しても、保留は増えません（「保留MAX」と表示）。
- 図柄は奇数（1・3・5・7・9）でそろうと確変、偶数でそろうと通常の大当たりです。

## 問題のジャンル

| ジャンル | ★1 | ★2 | ★3 |
|---|---|---|---|
| オームの法則 | A・Ω・V（整数） | mA と A の換算 | mA と kΩ、小数 |
| 合成抵抗 | 2個の直列・並列 | 3個の直列・並列 | 直列と並列の組み合わせ（回路図つき） |
| モル計算 | 1段階の変換（例：質量→mol） | 2段階の変換（例：質量→粒子数） | 分子量が複雑な物質（H₂SO₄、C₆H₁₂O₆ など） |

- モル計算で使う数値：原子量 H=1, C=12, N=14, O=16, Na=23, Mg=24, S=32, Cl=35.5, Ca=40、アボガドロ定数 6.0×10²³ /mol、標準状態の気体 22.4 L/mol
- 答えは必ず整数か小数第2位まで（粒子数は「a×10ⁿ」の a が小数第2位まで）になるように、答えから逆算して問題の数値を決めています。

### ミスの型（誤答の選択肢に付いているラベル）

誤答の選択肢は、次のような「典型的なミス」をしたときの計算結果から作っています。

| ミスの型 | 例 |
|---|---|
| 掛け算と割り算の取り違え | V＝I÷R と計算してしまう |
| 公式の変形・使い方のミス | I＝R÷V と割る順番が逆、3個の並列に「積÷和」を使う |
| 単位換算の桁ずれ | mA を A に直し忘れる |
| 並列で逆数の取り忘れ | 1/R₁＋1/R₂ の値をそのまま答える |
| 直列と並列の取り違え | 並列なのに足し算してしまう |
| 組み合わせの計算順ミス | どこが直列でどこが並列かを取り違える |
| 分子量の添字の掛け忘れ | H₂O を 1＋16＝17 とする |
| 原子量を分子量として使う | O₂ を 16 とする |
| 指数のずれ | 6.0×10²³ の 10 の何乗かがずれる |
| その他の計算ミス | 上のどれにも当てはまらないミス |

確変中の数値入力でも、入力した値が典型的なミスの計算結果と一致すれば、そのミスの型が表示されます。

## 起動方法（自分のパソコンで動かす）

1. [Node.js](https://nodejs.org/ja)（バージョン22以上）をインストールします。
2. このフォルダでターミナル（コマンドプロンプト）を開き、次を実行します（最初の1回だけ）。
   ```
   npm install
   ```
3. 次を実行すると、開発用のサーバーが起動します。
   ```
   npm run dev
   ```
4. 表示されたアドレス（`http://localhost:5173/rika/`）をブラウザで開きます。

**スマホで試すとき**：パソコンとスマホを同じWi-Fiにつないで `npm run dev -- --host` を実行し、表示された `Network:` のアドレスをスマホで開きます。

### そのほかのコマンド

| コマンド | 内容 |
|---|---|
| `npm test` | テストを実行（問題の生成を多数回まわして正しさを確認、抽選を大量にシミュレーションして確率を確認） |
| `npm run build` | 公開用のファイルを `dist` フォルダに作る（型チェックも行う） |
| `npm run preview` | 作った公開用ファイルを手元で確認する |
| `npm run icons` | アプリのアイコンを作り直す（`scripts/make-icons.mjs`） |

## 公開手順（GitHub Pages）

公開は GitHub Actions で自動化してあります。**main ブランチに変更が入ると、テスト→ビルド→公開が自動で行われます。**

1. **最初の1回だけ**：GitHub のリポジトリ画面で **Settings → Pages** を開き、
   「Build and deployment」の **Source** を **「GitHub Actions」** に変更します。
2. 作業用ブランチの変更を main に取り込みます（プルリクエストを作って「Merge」）。
3. リポジトリの **Actions** タブで「GitHub Pages に公開」が動きます。緑のチェックになれば完了です（数分かかります）。
4. 次のアドレスで遊べます： **https://konja9.github.io/rika/**

- テストが1つでも失敗すると公開されません（まちがった状態で公開されるのを防ぐため）。
- リポジトリ名を変えた場合は、`vite.config.ts` の `const BASE = '/rika/';` を新しい名前に変えてください。

### スマホのホーム画面に追加する

- **iPhone（Safari）**：共有ボタン → 「ホーム画面に追加」
- **Android（Chrome）**：右上のメニュー → 「アプリをインストール」または「ホーム画面に追加」

一度開けば、次からはオフラインでも遊べます。新しい版を公開すると、次にアプリを開いたときに自動で入れ替わります。

## 数値を調整するには

当たりやすさ・出玉・確変・基準時間・苦手の出し分けなどの数値は、すべて **`src/config.ts`** の1か所にまとめてあります。
ここの数字を書きかえて保存すると、ゲームに反映されます（`npm run dev` で動かしている場合はすぐに反映）。

```ts
hitRate: {
  normal: { white: 0.15, blue: 0.22, green: 0.3, red: 0.45, gold: 0.65 },  // 0.15 = 15%
  kakuhen: { white: 0.3, blue: 0.4, green: 0.5, red: 0.65, gold: 0.85 },
},
payout: { normal: 1000, kakuhen: 1500 },  // 出玉
kakuhenRate: 0.5,                          // 確変に入る確率
kakuhenQuestions: 8,                       // 確変の問題数
```

テストは `config.ts` の値を読んで確かめるので、数値を変えてもテストはそのまま使えます。
ただし「色が上がるほど当たりやすい」「確変中は通常より当たりやすい」という決まりを破る数値にすると、テストが失敗して知らせます。

## 記録・バックアップ・リセット

- 記録（持ち玉、正答率、ミスの型の回数、途中の保留や確変の状態）は、**その端末のブラウザの中（localStorage）** に自動で保存されます。
- **設定 → バックアップ** で、記録をJSONファイルに書き出したり、コピーしたりできます。機種変更のときは、書き出したファイルを新しい端末で「ファイルから読み込む」と引き継げます。
- **設定 → リセット** で、すべての記録を消して最初からにできます（2回確認します）。

---

## 注意

- iPhone は振動に対応していません（Android の Chrome などでは振動します）。
- マナーモードのときは効果音が鳴らないことがあります。
- ブラウザの「履歴・サイトデータの消去」をすると記録も消えます。ときどきバックアップしておくと安心です。
- 画像・Webフォント・音声ファイルは使っていません。効果音は Web Audio API でその場で作っています。

## ファイル構成

```
src/
├── config.ts          ★ 確率・出玉・確変などの数値（ここだけ変えれば調整できる）
├── main.ts            起動と画面の切り替え
├── core/              乱数、数値の丸め・表示、型の定義
├── questions/         問題の生成
│   ├── ohm.ts           オームの法則
│   ├── resistance.ts    合成抵抗
│   ├── mole.ts          モル計算
│   ├── mistakes.ts      ミスの型の一覧と解説文
│   ├── choices.ts       4択の選択肢を作る共通処理
│   └── index.ts         出題の選び方（苦手の出し分け）、数値入力の答え合わせ
├── game/              保留・抽選・確変・出玉（画面なし）
├── storage/save.ts    保存、バックアップ、リセット、記録の集計
├── audio/             効果音（Web Audio）、振動
└── ui/                画面（タイトル、プレイ、盤面、問題、回路図、記録、設定）とCSS
tests/                 テスト（Vitest）
scripts/make-icons.mjs アイコンを作るスクリプト
.github/workflows/     自動テストと自動公開の設定
```
